# Backlog Tracking Templates

Use these templates to create consistent backlog views across product, research, and engineering streams. Copy the relevant section into a working document or issue tracker and populate the fields.

## Feature Development Template

| Field | Description |
| --- | --- |
| **Title** | Short, action-oriented summary of the capability. |
| **Problem statement** | What user or workflow gap does this feature address? |
| **Outcome metric** | Quantitative signal that will prove the feature is successful. |
| **Key tasks** | Bullet list of implementation subtasks or experiments. |
| **Dependencies** | Links to prerequisite backlog items, datasets, or approvals. |
| **Risks & mitigations** | Known uncertainties and the plan to de-risk them. |
| **Target release** | Milestone or sprint where the feature should land. |
| **Owner** | Directly responsible individual. |

## Research Experiment Template

- **Hypothesis**: What behaviour or relationship are we attempting to validate?
- **Dataset**: Source, coverage, and freshness expectations.
- **Methodology**: Models, statistical tests, or tooling to be applied.
- **Success criteria**: Quantitative thresholds for acceptance.
- **Review cadence**: Frequency for status syncs and result sharing.
- **Next actions**: Immediate follow-ups once the experiment concludes.

## Operational Runbook Template

1. **Runbook title**: Name of the process being executed.
2. **Trigger**: Events or schedules that require the runbook.
3. **Inputs**: Configuration, credentials, or data required to start.
4. **Step-by-step procedure**: Ordered checklist for execution.
5. **Validation**: Logs, dashboards, or metrics that confirm success.
6. **Rollback**: Steps to revert if the process fails.
7. **Post-mortem notes**: What to record if anomalies occurred.

> _Tip_: Include status emojis (🚧 in progress, 💤 blocked, ✅ done) alongside backlog items when tracking progress in shared docs.
